Sistema Automatizado de Backups con Regla 3-2-1

Protección integral y redundante para la base de datos sakila en MariaDB: copias en almacenamiento local, disco externo NTFS y la nube de Cloudflare R2, con orquestación mediante cron y disparo manual bajo demanda vía bot de Telegram con n8n.

Automatización con cron

Ejecución periódica desatendida programada diariamente a las 2:00 AM (probada cada 5 min). Entorno con rutas absolutas e independientes de sesión interactiva.

Disparo Manual vía Telegram

Bot en Telegram que recibe /backup Sakila2026!. Conectado a n8n mediante túnel HTTPS cloudflared, ejecutando el script y devolviendo un reporte legible con emojis.

Retención Automática de 7 Días

Auto-limpieza integrada que purga copias antiguas tanto en local (find -mtime +7 -delete) como en Cloudflare R2 (rclone delete --min-age 7d), previniendo saturación.

Mínimo Privilegio & Credenciales

Usuario MariaDB backup_user con solo lectura sobre sakila.*. Credenciales protegidas en ~/.my.cnf con permisos 600 y token R2 exclusivo para el bucket.

Mecanismos de Disparo y Orquestación
Disparador Automático: cron Tiempo

Demonio de sistema Linux que ejecuta ~/backup_db.sh bajo el crontab del usuario kamscript. Lee ~/.my.cnf automáticamente.

0 2 * * * /home/kamscript/backup_db.sh
Disparador Manual: Telegram + n8n Evento

El usuario envía /backup Sakila2026! al bot @backup_kamscript_bot. Telegram notifica al webhook a través del túnel cloudflared. n8n valida la clave, ejecuta el script, procesa el stdout con regex y responde el reporte.

Telegram ➔ cloudflared ➔ n8n ➔ backup_db.sh ➔ Reporte
Stack Tecnológico

Herramientas y por qué se eligieron

Cada herramienta fue seleccionada por sus ventajas técnicas operativas, robustez ante fallos, compatibilidad con la regla 3-2-1 y costo cero.

MariaDB

Base de Datos Relacional

Motor SQL donde reside la base académica sakila. Se eligió por su alto rendimiento, compatibilidad con mysqldump para bloqueos consistentes de tablas (LOCK TABLES) sin interrumpir lecturas, y su sistema granular de privilegios que permite crear usuarios dedicados de sólo lectura (backup_user).

Ver módulo

GNU Bash

Scripting & Orquestación

Intérprete de comandos estándar en Linux donde se desarrolló ~/backup_db.sh. Se eligió por permitir set -o pipefail (garantizando que fallas en el dump no se oculten tras el gzip), manejo nativo de códigos de salida ($?), redirecciones duales con tee y chequeo condicional del disco externo con mountpoint -q.

Ver módulo

cron

Planificador de Tareas Linux

Demonio residente del sistema operativo que automatiza la ejecución periódica sin interfaz gráfica. Se seleccionó porque corre en segundo plano como el usuario kamscript, cargando su $HOME y el archivo ~/.my.cnf sin solicitar contraseñas, ejecutando a las 2:00 AM con cero consumo de memoria residual.

Ver módulo

rclone

Sincronizador Cloud CLI

Conocido como la "navaja suiza" del almacenamiento cloud. Se eligió por su soporte nativo para Cloudflare R2 vía protocolo S3, cifrado HTTPS en tránsito, capacidad de operar con la bandera no_check_bucket=true (esencial con tokens limitados a un solo bucket) y comandos integrados de retención como --min-age 7d.

Ver módulo

Cloudflare R2

Almacenamiento de Objetos S3

Destino offsite de la Copia 3. Se eligió por su generosa capa gratuita de 10 GB (los dumps de sakila pesan solo ~700 KB, resultando en un costo real de $0), cero tarifas de transferencia de salida (egress fees), alta durabilidad geográfica y generación de API tokens con permisos acotados estrictamente a un único bucket.

Ver módulo

n8n

Orquestador de Workflows

Motor de automatización basado en nodos instalado localmente con npm (sin Docker). Se seleccionó para recibir los webhooks de Telegram, validar la clave de seguridad (Sakila2026!), disparar backup_db.sh mediante el nodo Execute Command y transformar el log técnico mediante regex a un mensaje amigable con emojis.

Ver módulo

Telegram Bot

Interfaz de Usuario Móvil

Canal de disparo bajo demanda y reporte instantáneo. Permite que cualquier usuario autorizado, desde cualquier dispositivo y sin acceso SSH al servidor, ejecute /backup CLAVE y reciba en segundos la confirmación visual (✅/⚠️/❌) del estado de las 3 copias, tamaño y retención.

Ver módulo

XAMPP

Pila Web Local

Entorno de laboratorio preconfigurado que aloja el servidor MariaDB 10.4.32 y sus binarios de administración cliente en /opt/lampp/bin/ (incluyendo mariadb y mysqldump). Facilita el despliegue del esquema y datos de muestra de sakila.

Ver módulo

Linux

Sistema Operativo Host

El sistema operativo anfitrión. Proporciona la robustez de permisos POSIX (chmod 600 para salvaguardar contraseñas), montaje seguro de discos (mountpoint, lsblk), compresión eficiente (gzip) y el subsistema de crontab multiusuario.
